## Design decisions

1. **Separate URL handler** (`hammerspoon://operations/run`) — preserves `guide.lua` behavior and isolates allowlist security.
2. **JSON file bridge** — no localhost server; HTML polls `runtime/*.json` with cache-busting.
3. **Reuse existing modules** — layouts, windows, terminal_ops, verify, guide called directly.
4. **Async HTTP only for Ollama/n8n** — sync checks for filesystem/process; score updates after HTTP completes.
5. **Dark dense UI** — inline CSS, system fonts, no CDN, matches existing guide palette.
6. **Protected refresh** — `pcall` around refresh; individual check failures do not crash Hammerspoon.

## Known limitations

1. **file:// fetch** — works in Safari for same-directory JSON; Chrome may block — document in OPERATIONS_CONSOLE.md.
2. **Reload churn** — editing `~/.hammerspoon` triggers path watcher; can duplicate start events during development.
3. **Hammerspoon Console** — no guaranteed API to open Console programmatically on all versions.
4. **n8n process detection** — `pgrep -f n8n` may match unrelated processes.
5. **Guide actions** — not mirrored in event log unless routed through `operations/run`.
6. **Score weighting** — heuristic; tuned for visibility not production SLOs.

## Rollback procedure

```bash
BACKUP=~/.hammerspoon/backups/operations-console-20260710-102621
cp "$BACKUP/init.lua" ~/.hammerspoon/init.lua
cp "$BACKUP/USER_GUIDE.html" ~/.hammerspoon/USER_GUIDE.html
rm -f ~/.hammerspoon/modules/operations_console.lua
rm -rf ~/.hammerspoon/runtime ~/.hammerspoon/docs
echo "hs.reload()" | hs
```

Backups are never auto-deleted.
